# App 隐私申报核对 · 1.1.0（2）

这是发布者的工作表，不是已经提交的 App Store 隐私答案。静态代码说明哪些数据流动；服务商协议、实际保留和账户设置需要额外核实。Apple 的「收集」涉及数据离开设备后是否被开发者或第三方保留超过实时完成请求所需的时间。用户主动提供、使用自己的 Key 或没有广告 SDK，都不能单独决定答案。[Apple App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)

| 数据 / 行为 | 当前实现 | 申报前需确认 |
|---|---|---|
| 输入、模型回复、最近对话、相关已收藏记忆、任务和工具上下文 | 最近最多6条对话（限字数）和匹配记忆可用于 AI 请求；收藏记忆可在切换服务商后发送给新服务商 | 服务商 API 保留期限、是否用于训练/改进、适用目的；重点核对 User Content 类别 |
| API Key、模型、请求头 | Keychain 保存；请求给对应服务商验证 | 服务商是否把请求及保留内容关联到其账户；不得自动填写「不关联用户」 |
| IP 地址和网络日志 | 网络服务可获取连接信息 | 服务商实际日志、保留、用途及是否推断位置；代码无 GPS 读取 |
| 本地记忆和运行记录 | Application Support 中保存；记忆用于后续检索；运行指标本地统计 | 任务历史最多50条、旧评估最多1,000条、手动收藏记忆最多200条；仅本地部分与发送内容分别核对；系统备份未明确排除 |
| 支持请求 | 用户可进入公开 GitHub Issues，维护者可见提交内容 | 支持数据保留、发布主体联系方式；不要把公开 Issue 当私密渠道 |
| 广告、追踪标识、统计 SDK | 未见内置广告、IDFA 请求或第三方统计 SDK | 最终发布包和所有实际服务仍需核对；不能由此推导所有数据都不收集 |

## 还需补齐的事实

- 每个供应商的**API** 数据协议、保留选项、账户关联、处理地区及删除机制。消费级聊天产品的政策不一定适用于 API。
- 发布者的真实名称、可用联系渠道和支持请求处理规则。
- 第三方对用户数据的保护是否满足本 App 所作承诺和 Apple 要求；不能在未验证时虚构「同等保护」保证。
- App Store Connect 对每类数据的用途、与身份关联、追踪答案；本表没有代替发布者填入未知值。

## 本次代码对应的控制点

- 「我的 → API 配置」中按服务商显示目标和数据说明，保存单独共享选择。
- `NexusClient` 在发出网络请求前检查该服务商的选择。
- 「我的 → 隐私政策」显示随包发布的政策；网页版本需同步。
- 使用系统分享结果时，内容交给用户选择的 App/接收方；用户手动收藏的记忆、持久化任务历史须在政策中说明。
- 关闭共享开关并保存可阻止之后的请求；删除本地内容不会删除远程请求副本。
- 新写入的 Keychain 条目采用 `WhenUnlockedThisDeviceOnly`；不能由此宣称旧备份或用户创建的副本都已消失。

上述事实据 `NexusClient.swift`、`NexusProviderRequests.swift`、`ChatViewModel.swift`、`NexusKeychain.swift`、`NexusMemory.swift`、`NexusEvaluation.swift`、`NexusDataReset.swift` 和 UI 代码核对。服务商最新说明链接见 `PRIVACY_POLICY.md`。
