# 大脑网关故障：aquan.love 报 530/1016，怎么修（2026-08-17）

## 症状

神枢在 Telegram 里回话变成一句错误提示：

> `https://aquan.love` 报错 HTTP 530：error code: 1016。
> 去「设置 · 大脑模型 / 算力接口」检查网关地址、密钥与额度后再试。

（末尾带「枢 核… 映… 态…」坐标签名 = 这话确实是神枢自己发的，说明 TG 链路是通的，
挂的是它背后的大脑。）

## 根因（实测，非推测）

`aquan.love` **根本没有 DNS 解析记录**：

```
aquan.love      → 解析失败（No address associated with hostname）
www.aquan.love  → 47.79.228.95   ← 只有 www 子域有记录
```

Cloudflare 的 **error 1016 = Origin DNS error**，定义就是「这个域名在 CF 上开了代理，
但它指向的源站主机名解析不出来」。神枢的大脑网关配在 `aquan.love` 上，
所以每次调大脑都撞在这堵墙上 → 神枢够不着自己的脑子。

## 修法 A（推荐：不用部署任何东西）

神枢的大脑不一定要经过自建中转站。直接指向 Anthropic 官方接口即可，
**中转站那一跳纯属绕路，绕路的那一段还坏了**。

在神枢「设置 · 大脑模型 / 算力接口」里填：

| 字段 | 填什么 |
|---|---|
| 网关地址 | `https://api.anthropic.com` |
| 密钥 | 你的 `sk-ant-oat01-…` 令牌（**不要写进任何文件或仓库**，只填进设置界面） |
| 模型 | `claude-sonnet-5`（日常）或 `claude-opus-5`（重活） |
| 方言/厂商 | anthropic（一般自动识别，不用手填） |

**神枢已经内建支持这种 OAuth 令牌**：`buildBrainReq` 里判断 `sk-ant-oat` 开头就自动改用
`Authorization: Bearer` + `anthropic-beta: oauth-2025-04-20` 头，不用改代码。

已实测该令牌有效，可用模型含 `claude-opus-5` / `claude-sonnet-5` / `claude-fable-5`。

## 修法 B（想保留自建中转站才用）

`claude-proxy` 仓库就是那个中转站（转发到第三方商家 API `apiclaude.cc`）。若要它活过来，
**别再走「域名 → 源站服务器」这条路**（1016 就是这么来的），改成部署为 Cloudflare Worker：

```bash
cd claude-proxy
npx wrangler deploy                      # wrangler.toml 已配好 UPSTREAM_URL
```

然后在 Cloudflare 面板给 `aquan.love` 加一条 **Workers 路由**（`aquan.love/*` → `claude-proxy`）。
Workers 路由不需要源站，天然不会再出 1016。

## 顺带提醒

- 密钥一旦贴进聊天/截图/提交记录就算暴露，用完去 Anthropic 后台换一把新的。
- 神枢支持最多 9 个大脑并带故障转移（`config.brains`），可以官方接口 + 中转站各配一条，
  一条挂了自动换下一条，比单点可靠。
