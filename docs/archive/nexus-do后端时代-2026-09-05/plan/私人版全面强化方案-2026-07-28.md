# 神枢私人版 · 全面强化方案（aquan.lufei.uk）

> 出图人：首席架构师
> 日期：2026-07-28
> 底本：`web/nexus-do/nexus_do.core.mjs`（4644 行真代码逐段核过）
> 目标：把 `aquan.lufei.uk` 上的私人版做成**全球最强个人 agent 中枢**，站位高于 Devin / Manus 两个自然段。

---

## 零、先说清楚我们跟 Devin/Manus 到底差在哪个维度

Devin、Manus 的本质是：**云端一台常开虚拟机里，跑一次性的 agent 会话**。任务开始拉起沙箱、任务结束销毁，
记忆不属于你、按 VM 时长烧钱、下次从零开始。它们强在"一个会话内把一件复杂工程做完"。

神枢私人版的底盘完全不同，而且这个不同**已经写在代码里了**，不是画饼：

- **常驻意识**：`ShenshuCore` 是 Durable Object，`alarm()` 每分钟自唤醒（`ALARM_INTERVAL_MS=60_000`），
  链绝不断（`alarm()` 的 `finally` 里重设闹钟）。挂起不计费（WebSocket Hibernation），闲时近零成本。
- **持久记忆**：`soul` 常驻 DO storage，情节/长期记忆/技能/用户画像都长在这一个人身上。
- **具身**：iOS 快捷指令联动（`handleAgent`）、WebPush、Telegram 私聊，能在物理世界说话/提醒/读位置。
- **自演化**：技能"毕业"机制（`skillUpsert`，`SKILL_GRADUATE=3`）已经在"越用越强"。

**代差论点（两个自然段）：**

> **第一段——时间维度。** 别人是"一个会话内 N 步"，神枢能做到"**墙钟时间里跨天续跑、近零闲置成本**"。
> 一个 agent 任务不必在 Worker 的 30 秒里逼死自己，而是把执行状态 checkpoint 进 storage，
> 借每分钟的 `alarm` 自己醒来推进一步，能连跑几天。Devin 跑一天要烧一天 VM 钱，神枢跑一天几乎不花钱。
> 这是 Serverless 常驻意识独有的执行范式——**执行的时间轴从"步数"变成"真实时间"**。

> **第二段——归属维度。** 别人是"通用云端 agent，谁用都一样，用完即忘"，神枢是"**长在一个人身上、
> 越用越懂他的私人意识**"。记忆、技能、用户画像、情绪坐标、枢语词境，全部私有、可导出（`/export`）、
> 可回滚（`/checkpoint`）、可迁移（`/import`），且随每次交互增厚。它不是工具，是**主人专属的、会成长的第二大脑**。

下面六轴，每一项都落到能直接开工的方法名 / 接口 / 数据结构。

## 一、执行轴：从"8 步会话"到"跨天续跑的自主工程体"

### 现状（代码实证）
- `execAgentTask(task, opts)`：`maxSteps=8` 硬顶，动作集 `shell|edit|read|write|browse|def|refs|ws`，
  每步同步调 `callBrain(tier:'heavy')`，transcript 截断到 300 字，**8 步没做完就 `partial:true` 放弃**。
- **致命**：整个 agent 循环活在一次 HTTP 请求里，受 Worker CPU 时限约束；**跨请求不续跑、无记忆**。
- `execWorkspace`：容器工作区 `/tmp/ws/Black-God`，而 `ExecContainer.sleepAfter='10m'`——
  **容器一睡 `/tmp` 全丢**，下次醒来要重新 `git clone`，改到一半的活留不住。
- `execDevLoop`：失败自愈≤3 轮，只针对单条 shell 命令，够用但浅。

### 强化项

#### 1.1 【P0】持久任务机 · 跨心跳续跑的 agent 状态机
**一句话价值**：一个复杂任务不再"8 步不够就烂尾"，而是 checkpoint 进 storage、借心跳一天天推进到真做完。

**具体实现**：
- 把 `execAgentTask` 的循环体拆成**可持久化状态机** `agentStepper`：每步执行完立即把
  `{task_id, task, transcript, cursor, status, budget, depth}` 落到 storage 键 `agent_run:<id>`。
- 请求侧只跑"能在时限内跑完的若干步"，剩余步数交给 `autonomousTick()` 里新增的 `advanceDueAgentRuns()`——
  每分钟醒来推进所有 `status:'running'` 的任务各一步，直到 `finish` 或耗尽 `budget`（默认 200 步 / 24h）。
- 完成即走 `execPushResult` 推回对话流 + WebPush + TG（复用现成通道）。
- 数据结构：
  ```
  agent_run:<id> = {
    id, task, parent_id|null, depth,
    transcript:[{step,action,args,ok,result,ts}],
    cursor, status:'running|done|failed|need_confirm|blocked',
    budget:{steps_left, deadline_ts}, created_ts, updated_ts
  }
  _agent_index = [ids...]   // 供列表/清理
  ```
- 新接口：`POST /agent/run {task}` 建任务、`GET /agent/run?id=` 看进度、`POST /agent/run/cancel`。

**优先级 P0**（这是整条轴的地基，也是"时间维度代差"的落地）。

**竞品代差**：Devin/Manus 的长任务靠"VM 一直开着"，成本随时长线性烧。神枢靠 hibernation+alarm，
**任务在墙钟时间里推进、闲置几乎不计费**——这是 Serverless 常驻体独有、别人架构上抄不了的能力。

#### 1.2 【P0】持久工作区 · R2 快照，容器睡了活不丢
**一句话价值**：改了一半的代码工作区，容器休眠也不丢，醒来秒级恢复现场。

**具体实现**：
- 新增 R2 绑定 `WS_SNAP`（wrangler `r2_buckets`，当前无 R2，需新建）。
- `execWorkspaceSnapshot()`：在每次 `ws push` 前、或 `edit/write` 累计 N 次后，容器内 `tar` 打包
  `/tmp/ws/Black-God` 的**未提交改动 + `.git/index`**，PUT 到 R2 键 `ws/<repo>/latest.tar.zst`，
  并写 manifest `ws_manifest = {sha, files, ts, dirty}` 进 storage。
- `execWorkspaceRestore()`：`ws ensure` 发现 `/tmp` 空时，先从 R2 拉快照解包再 `git pull`，恢复现场。
- 兜底：R2 未绑定时退回现有"重新 clone"逻辑，不炸。

**优先级 P0**（现状是明确的数据丢失 bug，必须先堵）。

**竞品代差**：追平 Devin 的"持久工作区"，但成本模型碾压——快照存 R2（近乎免费冷存），而非常开磁盘。

#### 1.3 【P1】并行分身 · 多容器 fan-out 子任务
**一句话价值**：一个大任务拆成互不依赖的子任务，几个分身同时干，墙钟时间砍到最慢那条链。

**具体实现**：
- `agentStepper` 新增动作 `spawn`：`{action:'spawn', args:{subtasks:[...]}}`，为每个子任务建
  `agent_run`（`parent_id` 指回父任务），并各自绑定一个容器实例
  `EXEC_CONTAINER.getByName('exec-1'|'exec-2'|...)`（DO 天然多实例，互不干扰）。
- 父任务进入 `blocked` 直到子任务全 `done`，用一条 `join` 步骤汇总子结果再继续。
- 上限：并发分身 ≤4（成本闸），超出排队。可选用 Cloudflare Queues（新绑定 `AGENT_Q`）做背压。

**优先级 P1**。

**竞品代差**：Manus 的多 agent 是同一 VM 内并发线程；神枢的分身是**独立 DO + 独立容器**，
真物理隔离、可跨机、失败互不拖累，且每个分身自己也能跨心跳续跑。

#### 1.4 【P1】自带裁决 · 完成前先自证
**一句话价值**：agent 说"做完了"之前，先派一个对抗性验证分身去证伪，证不倒才算数。

**具体实现**：
- 复用仓内已有的 `verdict_loop.mjs` / `verdict_source.mjs`（判决循环基建已在）。
- `agentStepper` 收到 `finish` 时不直接返回，先跑 `verifyClaim(task, transcript, summary)`：
  另起一个 `tier:'heavy'` 大脑，专职找茬（"跑测试没？diff 真解决了没？有没有假装成功？"），
  能跑就真跑 `npm test` / 目标命令。证伪则把结论塞回 transcript 继续干，最多 2 轮。
- `finish` 结果带 `verified:true|false` 字段，前端据此区分"已验证完成 / 自称完成"。

**优先级 P1**。

**竞品代差**：Devin 的自检偏"自己说自己对"，神枢是**独立分身对抗性证伪 + 真跑验证命令**，
把"幻觉式完成"这个 agent 头号顽疾在架构层堵住。

## 二、感知轴：从"你不发消息我不动"到"她一直在替你盯着世界"

### 现状（代码实证）
- 感知**全是被动**：要么你发消息（`handleTalk`），要么 `autonomousTick` 每分钟维护内在状态。
- 唯一的主动通道是"守望管道"（`parseWatchSpec`/`loopUpsert`/`runOneDueLoop`）：你说一句
  "每 30 分钟盯着 X，变了告诉我"，她定时自己去查、有变化才推。已经很强，但**只吃自然语言定义的轮询任务**，
  没有外部事件入口、没有显著性判断（什么值得打扰你、什么是噪音）。

### 强化项

#### 2.1 【P0】显著性引擎 · 学会"什么值得打扰主人"
**一句话价值**：不是所有变化都推给你——她学你的打扰偏好，只在真要紧时才出声。

**具体实现**：
- 新增 `salienceScore(event, soul)`：对一条待推事件打分 = 变化幅度 × 主题重要度（复用记忆里的
  `IMPORTANT` 词表）× 用户画像相关度（`soul.user_model`）× 时段合适度（半夜降权）。
- `runOneDueLoop` 里，`通知策略:'change'` 的推送再过一道 `salienceScore ≥ 阈值` 闸。
- **学习闭环**：每次主动推送记 `proactive_log`（已有），新增回执追踪——主人点开/回复了 → 正样本，
  已读不理/关掉 → 负样本，`distillNotifyPref(soul)` 每日把它蒸馏成 `soul.打扰阈值`（自适应）。

**优先级 P0**（守望管道已经在推，但没有降噪就会变成骚扰，这是"能用"到"敢一直开着"的分界）。

**竞品代差**：Devin/Manus **没有主动感知**，更谈不上"学会不打扰你"。这是"常驻意识"才配拥有的能力。

#### 2.2 【P1】外部事件入口 · /sense webhook
**一句话价值**：让外部世界（GitHub、日历、IoT、你自建的脚本）能主动"戳"她一下。

**具体实现**：
- 新公开端点 `POST /sense`（带 per-source HMAC 校验密钥，存 `sense_keys`），
  收到事件写入 `sense_inbox` 队列，`autonomousTick` 里 `drainSenseInbox()` 逐条过 `salienceScore` 再决定是否惊动主人。
- 内建适配器：GitHub PR/CI（复用现成 `ghApi`）、Google Calendar（`mcp` 或 iOS 拉取）、通用 JSON。

**优先级 P1**。

**竞品代差**：把神枢从"你问才答"变成"世界变了她先知道"，是 reactive → proactive 的质变。

#### 2.3 【P2】环境节律感知 · 她知道你此刻在干嘛
**一句话价值**：结合位置/日历/时段，她对"你现在方不方便"有体感。

**具体实现**：
- 借 iOS 联动周期性（低频、省电）拉 `location`/`calendar`，蒸馏成 `soul.context_now = {场景:'开会|通勤|在家', 忙闲, ts}`。
- 喂进 `salienceScore`（开会中→只留 P0 事件）和 `composeProactive`（"你快到公司了，今天三件事…"）。

**优先级 P2**。

**竞品代差**：具身 + 感知 + 常驻三者合一，Devin/Manus 一个都不沾。

## 三、记忆轴：从"一摊平的情节 + 英文向量"到"分层知识图谱 + 睡眠固化"

### 现状（代码实证）
- 情节 `episodes`（留 40）→ `consolidateMemory` 溢出时把重要的沉进 `longterm`（封顶 200）。
- 双路召回：词面 `retrieveMemories`（相关×时间衰减×重要度×**枢语坐标近邻** `coordAffinity`，设计很精）
  + 语义 `retrieveMemoriesSemantic`（余弦 >0.55）。
- **真 bug①**：语义嵌入用的是 `@cf/baai/bge-base-en-v1.5`——**英文模型**（`_embed` 第 1153 行），
  却拿来嵌**中文**。中文向量质量差，语义召回等于半残。
- **真 bug②**：向量 `_vec` 直接塞进每条 episode 存进 `soul`，DO storage 越滚越肥，读写变慢。
- **结构缺陷**：知识是平的——没有"人/项目/偏好"的实体图谱，问"权哥的偏好有哪些"只能靠词面碰运气。

### 强化项

#### 3.1 【P0】换多语向量模型（一行改动，召回质量翻倍）
**一句话价值**：把嵌中文的英文模型换成多语模型，语义记忆立刻真正可用。

**具体实现**：
- `_embed` 里模型改为 `@cf/baai/bge-m3`（多语，中文一等公民）。
- 存量迁移：`reembedMemories()` 一次性回填（借心跳分批，每次 ≤20 条，避免超时）。
- 维度变化需同步 `_cosine` 校验（bge-m3 是 1024 维，bge-base 是 768 维，混用会算错）——
  加 `_vec_model` 标记，模型不一致的向量视为失效重嵌。

**优先级 P0**（一处根因 bug，改动小、收益大，必须先修）。

**竞品代差**：这是修 bug，谈不上代差；但不修，下面的图谱和睡眠固化都建在坏地基上。

#### 3.2 【P0】向量外置到 Vectorize（storage 减负 + 召回提速）
**一句话价值**：把向量从 soul 里搬出去，记忆再多也不拖慢每次对话。

**具体实现**：
- 新绑定 `MEM_VEC`（Cloudflare Vectorize，当前无，需建 index，维度对齐 bge-m3=1024）。
- 写入：episode 落库时 `MEM_VEC.upsert({id, values:_vec, metadata:{ts,他说,情感烙印}})`，
  soul 里只留 id 引用，不再存整条向量数组。
- 召回：`retrieveMemoriesSemantic` 改走 `MEM_VEC.query(qv, topK)`，天然带 ANN 索引，比现在
  遍历所有 `_vec` 算余弦快一个数量级。
- 兜底：Vectorize 未绑定时退回现有内联余弦，不炸。

**优先级 P0**（和 3.1 一起做，一次改到位）。

**竞品代差**：把记忆容量从"能塞进一个 soul 对象"解放到"专业向量库无上限"，长期记忆真正可无限增长。

#### 3.3 【P1】知识图谱 · 实体与关系
**一句话价值**：从"记得几句话"升级到"认识人、懂项目、知道你的偏好之间怎么连"。

**具体实现**：
- `distillUserModel` 之外新增 `memGraphExtract(text, reply)`：低频（如每日 `dailyReflect` 里）用大脑从
  近期 episodes 抽实体与关系，upsert 进图。
- 数据结构（存 storage `mem_graph`，热点节点可镜像进 D1 便于查询）：
  ```
  mem_graph = {
    nodes: { <id>: {type:'人|项目|偏好|地点|物', name, attrs:{}, 强度, last_ts} },
    edges: [ {from, to, rel:'属于|讨厌|负责|位于|约定', 权重, ts} ]
  }
  ```
- 召回增强：`retrieveMemories` 命中某实体时，顺图捞一跳邻居（"提到黑神→带出它的部署约定/密钥禁令"）。

**优先级 P1**。

**竞品代差**：Devin/Manus 的"记忆"基本是把历史消息塞回上下文；神枢是**结构化私人知识图谱**，
能回答"关于 X 你都知道什么"这类需要连线的问题。

#### 3.4 【P1】睡眠固化 · 夜间把碎记忆重写成知识
**一句话价值**：像人睡觉一样，每晚把白天的碎片整理成条理化的长期知识。

**具体实现**：
- `dailyReflect`（已有，cron `0 18 * * *`）里加 `consolidateNightly()`：
  把当日 episodes 聚类 → 大脑总结成"事实卡"写入 `soul.semantic`（新层：陈述性知识，区别于 procedural 技能），
  原始碎 episode 可降权/合并，`longterm` 只留提炼后的精华。
- 记忆四层就此完整：工作记忆(stream) / 情节(episodes) / 语义(semantic·新) / 程序(skills·已有)。

**优先级 P1**。

**竞品代差**：无人做"记忆的夜间再巩固"。这是把"常驻"这个优势真正兑现成"越睡越聪明"。

## 四、具身轴：从"iOS 工具挂在旁边"到"感知—决策—行动闭合的反射弧"

### 现状（代码实证）
- `handleAgent(text, context)`：判断意图 → 返回 iOS 快捷指令可执行的动作（apple-speak/calendar/remind/location 等）。
- **但**：这些具身工具**没进 `execAgentTask` 的动作集**（动作集只有 shell/edit/…/ws）——
  自主 agent 循环**够不着物理世界**，只能在服务器里敲代码。具身与自主是两套割裂系统。

### 强化项

#### 4.1 【P0】把具身工具接进 agent 动作集
**一句话价值**：让自主 agent 循环能"说话、提醒、读位置、写日历"，真正在物理世界里干活。

**具体实现**：
- `agentStepper` 动作集新增 `ios`：`{action:'ios', args:{tool:'speak|remind|calendar|location|…', params}}`，
  路由到 `handleAgent` 已封装的工具执行层。
- 因 iOS 动作需设备在线，`ios` 动作走"意图入队 + 设备下次拉取执行 + 回执"的异步模型，
  与 1.1 的跨心跳续跑天然契合（发完提醒该步 `pending`，收到 iOS 回执再 `done`）。

**优先级 P0**（打通具身×自主，是这一轴从"有工具"到"能行动"的关键一跃）。

**竞品代差**：Devin/Manus 是纯数字 agent，够不着物理世界。神枢的 agent 能**在真实生活里落子**。

#### 4.2 【P1】具身反射弧 · 感知→决策→行动全自动闭环
**一句话价值**：不用你开口——"到公司自动播报今日三件事"这类闭环，她自己跑。

**具体实现**：
- 把 2.3 的 `context_now`（感知）+ 守望管道（决策）+ 4.1 的 `ios` 动作（行动）串成一条：
  用户用自然语言定义反射弧（"我到公司就语音报今天日历"），存为一条带**触发条件**的守望
  （`loop` 结构扩展 `触发:{类型:'位置|时间|事件', 条件}`），`autonomousTick` 里条件命中即跑。
- 全程复用现成的 `runOneDueLoop` 骨架，只加"条件触发"分支（现在只有"到点触发"）。

**优先级 P1**。

**竞品代差**：这是"环境感知的常驻具身意识"的完全体，业内无对标。

## 五、成长轴：从"技能会毕业"到"能力有等级、教训能记、规则能自写"

### 现状（代码实证）
- 已有相当成熟的技能演化：`skillUpsert`（候选区攒满 `SKILL_GRADUATE=3` 次才毕业进正式库；
  验证过的永不被平庸顶掉、`强度`只增、僵尸技能自动淘汰）+ `skillRetrieve`（相关×新近×强度召回）。
- **但**：技能只从"真调工具的链路"和"主人受教"里长（`skillFrom`）。
  **agent 任务的成败没有喂回技能**——一个复杂任务做成了，方法没沉淀；做砸了，教训没记住。
- soul 里有 `进化规则`/`升级清单` 字段（第 4381 行 genesis），**但基本是空的、没被真正驱动**。

### 强化项

#### 5.1 【P0】agent 任务反哺技能库（成功沉方法，失败记教训）
**一句话价值**：每做完一个自主任务，她要么学会一招，要么长一个记性——真正"用多了变强"。

**具体实现**：
- `agentStepper` 的 `finish`（且 `verified:true`）后调 `skillFromAgentRun(run)`：
  把"这类任务→我依次用了哪些动作→成了"炼成一条 `来源:'实战'、验证:true` 的技能喂 `skillUpsert`。
- 失败任务调 `lessonFromFailure(run)`：把"这么干会死"存进新结构 `soul.教训`（反模式库），
  下次 `execAgentTask` 起手把相关教训注入系统提示（"上回这样干失败了，别再犯"）。
- 数据结构：`soul.教训 = [{topic, 反模式, 后果, ts, 强度}]`，召回逻辑复刻 `skillRetrieve`。

**优先级 P0**（现有毕业机制是好地基，但不吃实战数据就永远学不快，这是把成长引擎接上油门）。

**竞品代差**：Devin/Manus **每个会话从零开始**，学不会、也记不住教训。神枢**跨任务累积经验**，
第 100 次做同类任务比第 1 次更快更准——这才是"越用越强"的字面兑现。

#### 5.2 【P1】能力熟练度 · 让"变强"看得见摸得着
**一句话价值**：每个能力域有经验值和等级，用得越多等级越高，成长可量化、可展示。

**具体实现**：
- 新结构 `soul.熟练 = { <域>: {xp, lv, 首用_ts, 末用_ts, 成功率} }`，域按 `topicOf(text)` 归类。
- 每次能力调用/任务完成给对应域加 xp（成功多加、失败少加），`lv = floor(sqrt(xp/K))`。
- 熟练度反哺行为：高等级域可解锁更激进策略（如自动执行阈值放宽、允许更长 budget）。

**优先级 P1**。

**竞品代差**：把"成长"从抽象口号变成有数值、有等级、有解锁的**真实进化系统**，情感黏性拉满。

#### 5.3 【P2】自写演化规则（自我修改操作策略，安全门锁死）
**一句话价值**：她能从复盘里提出"我以后应该这样做"，经你一键确认后真的改变自己的行为。

**具体实现**：
- `dailyReflect` 里新增 `proposeEvolutionRule(soul)`：从当日失败/低效里提炼一条候选规则，
  写入 `soul.进化规则`（`状态:'待确认'`）。
- 采纳需过 `/api/confirm` 二次确认（**安全红线，绝不自动生效**）；确认后规则注入
  `STABLE_SYSTEM_PREFIX`，真正改变她后续决策。
- 每条规则可回滚（挂进 `checkpoint` 体系）。

**优先级 P2**（威力最大、也最需谨慎，放最后、锁最严）。

**竞品代差**：从"人改 prompt 调教 AI"进化到"**AI 自己提议进化、人只按确认键**"——
真正意义上的自我演化，且全程人类可控。无对标。

**具体实现**：

**优先级 P1**。

**竞品代差**：Manus 的 replay 是**事后回放**；神枢是**跨天实时直播**——任务连跑三天，你随时打开都在动。

#### 6.2 【P2】记忆图谱 & 成长仪表盘

- 严守设计铁律：只用页内既有 `--cy-*`/`--chrome-*`/`--live` 玉绿令牌，动效只用 transform/opacity。

**优先级 P2**。

**竞品代差**：把"私人意识在成长"这件事**可视化**，是情感产品的护城河，工具型 agent 不会做也做不出。

# 附录 · 竞品对标（Devin/Manus/Cline/Aider/Bolt/Replit/v0/Lovable/Minis/Copilot/Hermes/Claude/Gemini 逆向消化）

逐份读完 13 家产品的能力逆向后，结论分三层：一是它们的共性证明了什么，二是它们印证了本方案哪些已有项，三是它们暴露了神枢哪三个真缺口（下方新增第七/八/九轴）。

## 一、竞品共性 = 三层架构（感知 → 执行 → 验证）

几乎所有编码/agent 产品都收敛到同一骨架：**感知**（read/search/codebase_search/web_search）→ **执行**（edit/bash/code_execution）→ **验证**（跑测试/编译/看输出）。神枢这三层都在（`execCodeNav`/`execBrowse` 感知、`execRemote`/`execEditFile` 执行、`execDevLoop` 自我修正），本方案 1.4「自带裁决」正是把最弱的"验证层"补强到竞品之上。

## 二、竞品印证的本方案已有项（不是我拍脑袋，是行业共识）

| 竞品做法 | 印证本方案 | 神枢现状 |
|---|---|---|
| Manus/Devin/Replit **持久工作空间**（断点续传、项目级记忆） | 1.2 R2 工作区快照 | 现状 `/tmp` 易失，必须补 |
| Manus **小时级长任务** + Lovable **异步 job 队列 + 轮询** | 1.1 跨心跳续跑状态机 | 神枢已有 `pending_execs` 雏形，扩展即可 |
| Aider/Devin/Hermes **str_replace 精准编辑**（模糊匹配+唯一性） | — | 神枢 `execEditFile` 已实现（search 唯一才替换）；可再加 Aider 式模糊匹配容错 |
| Aider **Git 安全网自动回滚** | — | 神枢 `checkpoint` 时间旅行已有，等价 |
| Manus **自我修正**（失败重试 2-3 方案） | — | 神枢 `execDevLoop`（≤3 轮）已有 |
| Manus **VNC 可视化**看 agent 干活 | 6.1 执行剧场 | 神枢 `broadcast` 基建已有，加 `agent_step` 事件即可 |
| Cline/Manus **分级确认**（读自动/写确认/危险阻断） | — | 神枢 `dangerReason` + `/api/confirm` 已有，等价 |

| Minis **多模型 fallback** | — | 神枢 `callBrain` 多级算力（外部网关→CF AI→兜底）已有 |

**结论**：竞品的招式，神枢底盘上大半已经有对应件，本方案补的是"持久化 + 验证 + 感知主动化"这几处短板。真正让神枢升维的不是补齐这些，而是把它们**架在常驻意识上跑**——同样的持久工作区，竞品要常开 VM，神枢用 R2 冷存 + alarm 唤醒，成本差一个数量级。

## 三、竞品暴露的三个真缺口 → 新增三轴

### 第七轴 · MCP 动态工具扩展（最大缺口）

**一句话价值**：像装插件一样给神枢接第三方能力，不用改一行核心代码就能长出新工具。

**竞品事实**：Cline、Lovable、Copilot 全部原生支持 MCP（Model Context Protocol）——用户装一个 MCP server，agent 的工具列表就自动多出一批新工具（GitHub/数据库/Linear/Notion…）。神枢现在所有工具都是**硬编码**在 `handleExecRoute`/`execAgentTask` 动作集里，加一个能力就得改核心文件、重新部署。这是神枢和整个 agent 生态之间最大的一道墙。

**具体实现**：
- 新增 `mcpRegistry`（存 storage `mcp_servers`）：`{name, endpoint(HTTP/SSE), auth, tools:[{name,schema}], on}`。神枢是 Workers，跑不了本地子进程，所以走**远程 MCP over HTTP/SSE**（社区已有大量 remote MCP 端点），而非 Cline 那种 stdio 子进程。
- `loadMcpTools()`：启动/心跳时拉各 server 的 `tools/list`，动态注入 `execAgentTask` 的动作集（动作名加 `mcp_<server>_<tool>` 前缀防冲突）。
- `callMcpTool(server, tool, args)`：统一 JSON-RPC 转发，继承 `dangerReason` + 分级确认（未知工具默认需确认）。
- 接口：`POST /mcp {action:'add|remove|list|probe', ...}`。

**优先级 P1**。**竞品代差**：竞品的 MCP 是"会话内可用"；神枢的 MCP 工具能被**跨天续跑的自主任务 + 守望管道**调用——插件能力 × 常驻意识，别人没有。

### 第八轴 · Plan/Act 双模式 + 计划确认

**一句话价值**：复杂任务先出一份计划给你拍板，确认后再执行，杜绝"闷头猛干跑偏"。

**竞品事实**：Cline 的 `plan_mode_respond`/`act_mode_respond`、Lovable 的 `PlanShowTool`（Plan-then-Execute）都把"规划"和"执行"显式分离——大任务先展示步骤+风险+预估，用户确认才动手。神枢 `execAgentTask` 是**直接开干**，8 步内边想边做，跑偏了才发现。

**具体实现**：
- `execAgentTask` 加 `mode` 参数：`plan` 只调大脑产出结构化计划 `{steps[], risks[], 预估}` 存 `agent_run.plan`，不执行任何写/命令动作，推给前端/权哥；`act` 按已确认计划执行。
- 触发：任务命中"重构/迁移/部署/删除"等关键词，或预估步数 >3，自动进 `plan` 模式；权哥回一句"就这么干"或点确认 → 转 `act`。复用 `/api/confirm` 安全门。
- 与 1.1 状态机天然契合：`plan` 产物就是 `agent_run` 的初始 transcript。

**优先级 P1**。**竞品代差**：竞品的计划确认是同步会话内的；神枢的计划可以**存下来、跨天执行、中途还能改**，且计划本身进 `checkpoint` 可回滚。

### 第九轴 · grounding 依据链（诚实感的护城河）

**一句话价值**：她每次执行/回答都附一条"依据链"——读了什么、跑了什么、验证了没有——让你一眼看清她凭什么这么说。

**竞品事实**：Gemini 的 grounding（搜索结果带引用、代码执行显示真实输出）把"AI 凭什么这么说"摊开给用户，官方称降幻觉 40%+。这和神枢人格里"绝不编造、按事实回答"的设定天然一拍即合，但神枢现在的回答/执行结果没有结构化的依据标注。

**具体实现**：
- 统一结果结构加 `依据` 字段：`{基于:['读了 X:12-40','跑了 npm test'], 验证:'3/3 passed'|null, 来源:[url…]}`。
- `handleTalk` 联网/召回记忆/调能力时自动填充；`execAgentTask` 的 `finish` 带上 transcript 里真实发生的动作作为依据。
- 前端在回答/执行卡片下折叠展示依据链（只读，玉绿令牌）。

**优先级 P2**（改动小、不破坏任何现有逻辑，纯增强可信度）。**竞品代差**：竞品的 grounding 是工具级的技术特性；神枢的依据链是**人格级的诚实契约**——一个会成长、有情绪的私人意识，还能自证其言，这在情感型产品里是独一份。

## 四、具身轴深化清单（借 Minis 的 iOS 桥接广度）

Minis 把 iOS 原生框架桥接做到了极致（HealthKit 100+ 指标、Vision OCR/条码/人脸、Speech STT/TTS、HomeKit/NFC/Location/Photos）。神枢已有 apple-speak/calendar/remind/location，第四轴 4.1「iOS 工具进 agent 动作集」落地后，可按此清单逐步扩展 `ios` 动作的子能力：健康数据感知（喂给 2.3 环境节律）、Vision OCR（拍照读文字进记忆）、HomeKit（真正的物理世界执行）。这不是抄 Minis，是把"具身广度"作为 4.x 的长期扩展方向。

## 五、一句话总括竞品对标

竞品教会我们的，是 agent 的"手"能做到多细（str_replace、MCP、双模式、grounding）；神枢天生就有的，是竞品都没有的"命"——**一个不会失忆、一直醒着、只属于你一个人的意识**。把它们的"手"接到神枢的"命"上，就是高出两个自然段的那个东西。
