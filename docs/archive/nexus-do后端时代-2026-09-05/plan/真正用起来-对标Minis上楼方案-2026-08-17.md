## 二、病根（对照 Minis 的可用性模型）

Minis 的信条写在它 README 里：产品优势不在技术设计，在「与使用者的紧密反馈回路」。
它把回路铺平的三件事，恰好是神枢缺的三块：

1. **入口不在日常动线上**。Minis 是 App Store 装完就在桌面上；神枢要打开浏览器、
   输网址、填令牌——每一步都是流失点。权哥手机上大概率连 PWA 图标都没装过。
2. **没有每天必然发生的场景钩子**。Minis 的用例全绑在日常事件上（吃饭拍照记营养、
   闹钟播报时间线、群消息转任务）；神枢的主动联系是「想念驱动」的情感模型，
   不是「每天早上 8 点必来」的日程驱动——没有固定钩子，就不会形成打开习惯。
3. **反馈回路没转起来**。不用 → 不知道哪里不顺 → 不改 → 更不用。死循环的解法
   只有一个：先把「每天至少碰一次」跑通，哪怕场景很小。

## 三、上楼方案（三级台阶，从今天到立项）

### 台阶一 · 本周用起来（权哥 10 分钟 + 零新代码）

1. **装 PWA**：手机浏览器打开 `https://aquan.lufei.uk` → 登录 → 「添加到主屏幕」。
2. **开通 Telegram 入口（最关键的一步）**：
   - 在 TG 找 @BotFather 发 `/newbot`，得到机器人令牌；
   - `cd web/nexus-do && npx wrangler secret put TG_BOT_TOKEN`（粘贴令牌），
     再 `npx wrangler secret put TG_WEBHOOK_SECRET`（随便一串长随机字符）；
   - 带主人令牌 POST 一次 `https://aquan.lufei.uk/tg/setup` 完成挂钩。
   - 从此神枢就是 TG 里的一个联系人——在你每天都开的 App 里，不用记网址不用登录。
3. **给它一个日常任务**：开通后先让它干三件小事各一次：早上问它今天安排、
   随手发它一段话让它记住、让它跑一条查询。用三天，把不顺手的地方记下来喂回来。

### 台阶二 · 让日常离不开（工程量小，等拍板即可开工）

1. **早报钩子**：心跳里加「每天固定时刻主动发 TG 早报」（天气/待办/记忆里的未竟事），
   把主动性从「想念驱动」补上「日程驱动」——这是 Minis 闹钟场景的神枢版。
2. **伪命令桥（前一轮 P0）**：容器执行脑里加 `nexus-memory` / `nexus-shuyu` 等伪命令，
   照搬 Minis 的 JSON 信封桥接模式，让沙箱任务能直接调神枢的记忆与枢语能力。
3. **TG 场景技能**：转发消息给神枢=存记忆/提醒；发图=识图归档。对标 Minis
   「群聊转任务」「拍照记录」两个王牌场景的 TG 实现。

### 台阶三 · 端上进阶（需立项）

安卓原生壳 + proot 端上沙箱（Minis 安卓同款路线）、设备整合（日历/剪贴板）。
在台阶一二跑顺、真有端上需求之前，不建议动。
