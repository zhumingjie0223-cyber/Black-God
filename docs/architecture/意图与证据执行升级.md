# 意图与证据执行升级 · 1.4.0（24）开发版

用户输入先产生任务卡，之后才进入计划。任务卡包含目标、对象、约束、成功条件、缺槽、风险和可用工具；模型给出的槽位仅是候选，不能生成新对象或解除本地授权。规划与执行同时带入卡和召回来源，每轮原生请求都保留这些约束。

对象来源是最近用户明确提及的工作区文件、已确认记忆、带工具观测快照的历史任务和技能目录。相同文件的多个来源合并为一个对象。唯一命中时在答复开头说明假设；低风险含糊请求先读指定对象，高风险多对象先问一个关键问题。澄清回填保留原操作与约束，新的操作或取消按新要求重新处理。含糊指令不能通过 Shell 或嵌套执行绕过。

## 本地召回和数据边界

`NexusRecallIndex` 在内存中重建当前资料的向量索引，不持久化已删除记忆的向量。优先使用设备系统的中文句向量，缺失时用中文分词后的归一化词向量均值；不同语言和模型空间不混用。系统没有适用模型时明确使用词面召回。词面、语义和时间先验都有可区分的方法标记。工作区只索引文件名称，不读取文件正文，不跟随符号链接。近期闲聊和助手猜测不变成可执行对象。

情节存储最多100条用户目标及工具观测摘要，记录已选对象名称、稳定调用指针和有限输出快照，不把模型答复、推断或偏好当成事实。当前连接凭据按精确匹配隐藏，不能保证识别所有秘密。情节与会话同范围管理；清空当前对话及重启恢复清空会一并清除情节。全部会话清空还包括快捷指令和旧版情节文件。长期记忆及候选的确认机制和原存储格式保持兼容。

## 执行与复核

每步持有稳定来源标识及 `tool:<调用UUID>`。生成非空答复只记“已答复”；只有实际成功工具证据才记已验证执行。规划最多4步，任务所有模型请求（包括可选分类、原生工具回合及复核）共享20次上限。复核检查槽位、证据矛盾和越权，程序独立核对所需工具、数字结果、引用及失败状态；模型的 passed 不能盖过程序失败。最多修正一次，重用原步骤和证据。

所有文本、原生和枢语子工具调用都传递同一个授权检查。文件工具绑定卡中对象路径；Shell 绑定用户明确原始命令，模型不能替换命令或自行提供危险确认。运行时仍保留静态审计、配额和权限边界；这些防护不表示已经完成不可信程序的独立安全审计。

治理账本将只读网页检索与工作区权限分级。工作区列表、读取、写入、删除、恢复、下载及Shell都要求有效的30分钟租约；返回结果时再次核对租约及权限版本。只读网页工具同时保留自己的联网开关、明确网址和公共地址检查。未知工具不会因工作区授权而获得执行权限。

聊天和快捷指令都保留待澄清卡；短答只补原卡缺槽。检查点另存原卡种子，进度更新或中断恢复不会把“金边那份”误当成新的完整任务。取消和新动作不会继承旧删除权限。已执行的修改、删除、恢复等任务不能用“重新生成答复”重做；恢复策略由程序持久化，文件任务仅读取绑定对象核对现状，发送、付款和命令缺少独立核对工具时停在执行前。再次中断或重新生成仍只能核对，不把旧计划重放；重新操作需要新的完整指令。没有所需工具时明确保留能力缺口，不编造执行成功。

`workspace_write` 先原子保存真实旧状态，再调用原写入原语，成功返回备份ID。私有备份按工作区隔离，最多10份、每份完整归档不超过2 MiB（包含编码及元数据，因此接近2 MiB的旧文件可能被保守拒绝）。`workspace_restore` 需要备份ID、原路径和“恢复备份”，拒绝覆盖该次写入后再次被修改的目标；恢复旧字节或撤销新建都要读回核对。事务期间拒绝交错的 Shell 和外部导入。备份会保留在本机应用容器中，不属于清空聊天的范围。

## 模型分工与只读检索

在连接设置中可指定一个已保存并允许发送的连接做分类与槽填充，默认直接使用本地编译器。型号大小与实际能力由用户选择的服务商决定，应用不猜测；主连接负责计划、执行请求和收口。每个任务冻结两套连接和凭据，每次发送仍检查许可，失效配置不自动转向其他账号。分类失败可回退本地；分类输出不能改变风险授权。

`web_lookup` 只读取用户本次明确提供的公共 HTTPS 文档，查询词在本地匹配；它不是无地址的全网搜索。请求为GET，不发送聊天、查询词或模型密钥，禁用cookies、缓存、登录凭据和页面脚本，限制同站重定向、下载大小和时间。输出有来源网址和抓取时间，并标记未独立核实。DNS公共地址检查与底层请求再次解析仍有时间间隙，不能称为完整的网络隔离保证。

检索调用成功与资料命中分开判断。记忆、技能和网页要求有可检查的候选或片段，空结果、无效输出以及纯近期先验不能作为取得资料的证据。近期先验仍可用于编译前消歧；偏好事实检索只接受真正命中。执行引擎遇到空结果直接返回标准未找到提示，跳过模型汇总和自评，不展示夹带的偏好猜测。

## 验证与交付

`make test-intelligence` 调用 `tools/intelligence/run-tests.sh`，逐字编译实际核心源码并运行XCTest，网络和模型通过可检查的本地夹具注入；不会向真实模型发送请求。固定50句中文集核对对象、工具、澄清及风险标签，既不执行工具也不让模型自评。监测页使用同一评分器，保留逐句差异。

固定标签由开发侧编写，仍需独立人工核对和扩展真实歧义样本。50/50一致只能说明当前编译器符合预置标签，不能证明真实模型正确率。运行统计中的无警告答复率仍是运行统计，不能当作理解或智慧指标。

最终Linux实际执行259项XCTest，失败0、跳过0；实际聊天、快捷指令、治理账本、沙箱工具表和事务扩展一起编译，入口澄清、恢复、会话隔离与旧记录回归实际运行。50句的对象、工具、澄清、风险及全部条件均与预置标签一致。此前两个仓库的214项JavaScript／Python枢语测试和内置资源同步检查通过。完整Swift源码语法检查、改动格式检查及签名Swift安装脚本复验通过。

平台适配仅覆盖系统接口：SwiftUI模块只重导名称供不含界面的聊天状态模型编译，Combine不发送订阅事件，模型客户端拒绝真实联网，JavaScriptCore初始化拒绝执行，iSH运行时拒绝客体命令。聊天和治理类使用实际源码，不以替身替换它们的状态机或权限判断；这些验证仍不能替代Apple SDK链接。完整适配清单见 `tools/intelligence/README.md`。

新增 `.github/workflows/intelligence-core.yml` 在PR或main改动时运行固定签名工具链下的同一套回归并保留日志；现有iOS工作流继续承担Xcode测试与无签名构建。本轮只有Linux运行证据，尚未触发远程工作流。

Linux不验证SwiftUI链接、JavaScriptCore内置方言、Apple系统嵌入可用性、iOS订阅行为及真实iSH内核。最终源码需要在macOS运行 `make generate`、`make test-ios` 和 `make build`，再完成设备、实际模型、存储不足、后台中断、连接撤销和并发操作验收。本轮没有上传App Store或发布云环境。
