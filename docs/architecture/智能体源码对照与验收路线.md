# Black God：智能体源码对照与验收路线

检查日期：2026-09-09。范围是三个开源仓库的模型连接、工具循环、记忆、上下文和持久记录的重点路径，并非全面代码审计。参考仓库未修改，没有执行其安装脚本。本轮 Black God 的纠错代码独立实现，未复制 Hermes 或 Codex 的源码。

## 结论

Black God 应建立“模型能力 + 可靠工具执行 + 持续任务状态 + 可追溯记忆 + 真实评测”的体系。接入多个模型只是基础设施；更多工具、循环次数或自我复核不能证明达到了 ASI。这里的工程目标是提高可验证的复杂任务完成率，并降低错误完成声明、恢复失败和重复执行。

当前没有依据把 Black God 称为 ASI，也没有完成工业级验收。下列“已实现”和“待实现”严格区分。

### Minis：模型如何接入

`ProviderInstance.swift` 保存独立连接实例，因此同家多个账号、不同地址能够共存。`LLMProviderFactory.swift` 根据协议和认证创建具体客户端；`ProviderConfigStore.swift` 获取模型及连接凭据。`ModelGroupRouter.swift` 选择可用模型并支持 fallback/loadBalance；调用方仍需约束切换次数。`ModelUseOffloadBridge.swift` 将脚本的模型请求转给宿主，不能据此认为 iSH 自身产生了模型智能。[连接实例源码](https://github.com/OpenMinis/OpenMinis/blob/4ef29002e88db1e20e462ec2ff46916e8a7dcb45/src/ios/Providers/ProviderInstance.swift)、[适配工厂](https://github.com/OpenMinis/OpenMinis/blob/4ef29002e88db1e20e462ec2ff46916e8a7dcb45/src/ios/Providers/LLMProviderFactory.swift)、[模型组路由](https://github.com/OpenMinis/OpenMinis/blob/4ef29002e88db1e20e462ec2ff46916e8a7dcb45/src/ios/Providers/ModelGroupRouter.swift)。

Black God 已有 11 家入口、自定义接口、独立连接凭据、模型列表与手动模型 ID；支持 Messages、Chat Completions、Responses、Gemini generateContent 四种协议。模型组、OAuth、Azure 专有认证、完整多模态能力尚未实现；11 家入口不代表 11 家真实账号全部验收成功。

### Hermes：如何保留经验

`tools/memory_tool_store.py` 将一般记忆和用户信息分开，提供 add/replace/remove/batch，限制字符总量，并在锁内重新读取、原子写入。它不会无限追加所有聊天内容。`tools/session_search_tool.py` 搜索持久历史并保留来源与消息定位。`tools/skills_tool.py` 先展示名称和描述，需要时才读取完整技能；`tools/skill_manager_tool.py` 把流程经验保存为 SKILL.md 和相关资源。`agent/background_review.py` 还有有预算的后台记忆/技能整理流程。[记忆存储](https://github.com/NousResearch/hermes-agent/blob/b2aa855b626ff8688eb34b95c60ee8b6a4af3679/tools/memory_tool_store.py)、[技能读取](https://github.com/NousResearch/hermes-agent/blob/b2aa855b626ff8688eb34b95c60ee8b6a4af3679/tools/skills_tool.py)、[技能维护](https://github.com/NousResearch/hermes-agent/blob/b2aa855b626ff8688eb34b95c60ee8b6a4af3679/tools/skill_manager_tool.py)。

`agent/context_compressor.py` 在压缩时保留上下文结构，处理摘要截断、认证错误和不应被当成新指令的历史内容。不能只把长记录截成前几千字就声称有长期记忆。[上下文压缩](https://github.com/NousResearch/hermes-agent/blob/b2aa855b626ff8688eb34b95c60ee8b6a4af3679/agent/context_compressor.py)。

这些已检查路径主要更新外部记忆与技能文件，没有证明模型权重会在使用中自动变强。Black God 当前只具备用户记录的词面检索、历史截取和执行证据摘要，尚没有 Hermes 式的技能沉淀、版本回滚和分层记忆。

### Codex：如何持续执行和恢复上下文

`core/src/session/turn.rs` 根据模型是否需要后续工具回合、是否有用户新输入继续运行，同时检查上下文容量。`core/src/compact.rs` 构造替换历史并保留用户消息及压缩检查点。`rollout/src/recorder.rs` 将会话项目排队写入持久记录，提供显式 persist/flush 和加载历史路径。[执行循环](https://github.com/openai/codex/blob/c1f1467f3028bd433c8f2063ecc28dd5be206df6/codex-rs/core/src/session/turn.rs)、[上下文压缩](https://github.com/openai/codex/blob/c1f1467f3028bd433c8f2063ecc28dd5be206df6/codex-rs/core/src/compact.rs)、[记录器](https://github.com/openai/codex/blob/c1f1467f3028bd433c8f2063ecc28dd5be206df6/codex-rs/rollout/src/recorder.rs)。

记忆写入分为单会话提取和全局汇总：选择符合条件的历史、任务租约与退避、脱敏、生成摘要，再串行维护全局记忆。这比把一次回答直接当成永久事实更有约束。[记忆流水线说明](https://github.com/openai/codex/blob/c1f1467f3028bd433c8f2063ecc28dd5be206df6/codex-rs/memories/README.md)、[第一阶段代码](https://github.com/openai/codex/blob/c1f1467f3028bd433c8f2063ecc28dd5be206df6/codex-rs/memories/write/src/phase1.rs)。

Black God 已持久保存对话和 Linux 执行状态，重启会把未结束命令标为中断；目前不会自动重放。完整 Agent 计划、逐步工具证据和任务恢复检查点仍未持久化。

## 本轮已落地：复核后重新获取证据

之前：计划 → 工具执行 → 答复 → 复核 → 只改答复文字。缺少证据时，纠错过程不能再次执行工具。

现在：计划 → 工具执行 → 答复 → 复核；发现问题后，增加一个纠错步骤，可以调用现有工具检查，再用新证据复核一次。

- 文本工具协议和原生函数调用都使用同一个执行器；原始步骤和工具证据保留。
- 默认共用 20 次模型请求上限，纠错最多一个步骤、4 个模型回合；最多两次复核，避免无限自我修正。
- 纠错提示要求先检查当前状态，不因复核失败而整体重放原计划；这属于模型行为约束，不是任意副作用操作的幂等性证明。
- 请求不足、工具循环耗尽、无有效结果或复核仍失败时，明确返回未验证状态。纠错失败保留原答复，用户取消会终止流程。
- 模型复核仍可能出错；`reviewPassed` 只表示当前规则和模型复核通过，不等于每个外部事实都已独立验证。

修改位置：`ios-app/NexusExecutor.swift`、`ios-app/NexusReasoningEngine.swift`；新增测试位于 `tests/ios/NexusIntelligenceTests.swift`、`tests/ios/NexusNativeAgentTests.swift`。

## 后续实现与验收优先级

| 顺序 | 具体工作 | 验收方式 |
|---|---|---|
| 1 | 用真实账号验证每种协议，再扩展到所需服务商 | 每家完成文本、函数调用、错误凭据、取消与限流测试；按账号、模型记录结果 |
| 2 | 持久任务检查点与证据索引 | 强制退出后保留目标、约束、已完成步骤和未完成事项；恢复前检查实际状态，防止重复副作用 |
| 3 | 分层记忆与可追溯技能 | 用户事实、任务经验、流程技能分开；保留来源和验证状态，支持删除、更正和版本回退 |
| 4 | 长任务上下文管理 | 压缩后关键约束仍可恢复，未完成目标不丢失，旧摘要不能覆盖用户的新要求 |
| 5 | 按能力选择模型与显式备用组 | 用户选择可使用的服务商；区分认证、限流、协议错误；切换有上限，工具结果不能错配 |
| 6 | 长时间真实任务评测与资源限制 | 检查结果文件和外部状态，统计完成率、错误完成声明、恢复成功率、调用数、耗时与费用 |

建议首轮固定 20 个任务，覆盖计算/文件处理、跨轮约束、工具失败恢复、长历史、服务商异常五类；在至少三个真实模型上各重复三次。上述是待执行的评测设计，不是已有成绩。真实模型评测和传输/单元测试必须分开报告。
