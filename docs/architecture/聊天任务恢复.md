# Black God 聊天任务恢复升级

2026-09-09。本轮补上实际聊天执行器的持久任务记录，没有操作用户手机，没有发起真实模型 API 请求。

## 已实现

- 保存当前任务的原目标、连接/模型、验收条件、步骤状态、近期工具证据和待确认的工具名称。
- 每个工具执行前保存准备状态，返回后保存结果；保存失败会终止后续执行。调用已发生但结果未落盘时，保留“结果未知”的准备状态。
- 重启把运行中的任务标为中断，显示“继续任务 / 结束此任务”。启动不会自动调用模型或重放命令。
- 点击继续会把恢复资料带入规划和后续工具回合，要求先核实当前状态，只处理未完成内容。保留原用户消息，不重复追加。
- 恢复核对连接身份、地址、协议和模型；配置改变时提示切回原连接，不将旧恢复资料发送到另一个连接。
- 最终答复先写进任务记录，再保存聊天记录；两个写入之间退出后，下次启动按消息 ID 补回答复，避免重复生成。
- 复核有待确认事项时，答复仍显示，同时保留继续任务入口。
- 取消后的旧任务回调不能覆盖新任务的记录。用户可结束恢复任务；发送新问题会替换当前恢复记录。

## 存储与边界

聊天任务记录与对话存储在同一个应用支持目录中，使用独立 `.agent.json` 文件和原子写入、iOS 文件保护。只保留最近一个任务；不是完整事件日志。

每步结果最多约3000字符，最近24条工具证据每条约1000字符，保留截取提示；恢复资料最多约16000字符。保存前会隐藏当前连接的已知API密钥，不单独保存工具参数、原始脚本、认证头或服务商隐藏推理内容。工具输出和用户目标仍属于本地任务数据，可能包含其他敏感信息；不能把已知密钥替换当成全面秘密检测。

恢复属于根据检查点重新规划，不是从模型内部状态原位续跑。检查当前状态和不重复副作用的要求目前由提示和工具循环配合实现，不是任意脚本的幂等性保证。没有工具证据时，系统仍依赖模型正确识别不确定性。跨多次中断的资料会受摘要长度限制。

本轮覆盖聊天入口；App Intents 尚未接入此任务恢复记录。完整多任务列表、可查询的完整证据文件、长期记忆与技能版本管理仍待实现。
