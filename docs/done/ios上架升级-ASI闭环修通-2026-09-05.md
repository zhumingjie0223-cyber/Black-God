## 结论（2026-09-05 完成）

**起点**：main 上 iOS 编译不过（`NexusExecutor.swift` 大量协议/类型错误），且 UI 含 App Store 必拒内容
（黑客工具页 + NSFW 创作页）。根因是当天 "fable5.1" 系列提交引入了一套新工具协议
（`run(arguments:) -> String` + 引用型 registry），与原有 `NexusTooling.swift` 老协议
（`execute(_:) -> NexusToolResult` + struct registry）并存冲突，两套互不兼容、各自内部类型也对不上。

**落地三件事**：
1. **修编译**——统一工具协议为 `execute(_ call:) async -> NexusToolResult`，registry 改 class 供
   Runtime 与 Executor 共享；内置 clock/calc 改读 arguments 字典，calc 用安全递归下降求值器替换会崩的
   NSExpression。
2. **ASI 闭环真跑通（P0–P4）**——修「prompt ```tool 约定 ↔ 解析器」不一致（旧代码 prompt 写
   "TOOL: 名|参数"、解析器却只认 JSON，闭环从来没通过）；重写 `NexusToolCallParser`；模型目录归一为
   `NexusModelCatalog` 单一来源（消除四份漂移列表、去掉可疑第三方转售条目）；多服务商 Key 按 provider
   分存、设置页选择真正生效；请求体不下发原生工具 schema 避免文本闭环断链。
3. **上架合规**——下线无功能且含 NSFW 的创作页，Tab 收敛为 对话/能力/监测/我的；工具页从黑客工具改为
   展示真实执行闭环与工具总线；去人物向文案；移除未用的麦克风/相册权限；版本升 1.1.0/build 2；补中英
   发布说明。

**验证**：本仓无 Swift 测试基建、CI 仅 macOS 手动构建，为不再靠 CI 编译兜底，本机装 Swift 6.3.3 把
Foundation-only 核心搭成独立包 → 编译通过 + 29 项断言全绿（脚手架在 /tmp 不入库）；编译器实测抓到并修了
一处真 bug（算术求值器 `isAtEnd` getter 调 mutating）。`NexusCoreTests` 同源扩充随包留存。

**明确没做/留待后续**：SwiftUI/UIKit 层无法在 Linux 云机编译，最终需 macOS CI 或 Xcode 确认；
`CLAUDE.md`/`README.md`/`STRUCTURE.md` 仍把已删的 `web/nexus-do/` 当唯一部署主体、`Makefile`/
`check-sync.mjs`/`deploy-nexus.yml`/`nexus-do-ci.yml` 是死路径/僵尸工作流——已在 PR 里点名，宜专门收口。
