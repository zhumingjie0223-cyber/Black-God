# 神枢「真正可用」全天抢修实录（2026-08-17）

权哥早上一句「怎么样了」，本以为只是查状态，结果一路挖出的结论是：
**神枢从来就没真正能用过**。不是功能没做，是三条命脉各自断在不同地方，
而且互相遮掩，谁也没暴露出来。

## 一、查出并修复的真故障

### 1. 网页界面死了 15 天（最要命）

**症状**：页面打得开，但点不动；后来能点了，主内容又是一片黑。

**根因**：2026-08-02 那次「NavCore v3 导航重构」是一次**只做了一半的迁移**，
留下五处致命伤，一处遮着一处：

| # | 病 | 后果 |
|---|---|---|
| 1 | 旧 Tab 实现没删干净，与新实现的 `let _tabIdx` 重名 | 主脚本块**整块解析失败**，所有事件绑不上 |
| 2 | 多行欢迎语用单引号跨行 | 语法错误（被 #1 挡着看不见） |
| 3 | `doChat` 里 `if(navigator.onLine)` 整句丢失，只剩孤儿 `else` | 语法错误（被 #2 挡着看不见） |
| 4 | `showLock()` 被三处调用却从未定义 | 登录门永远弹不出来 |
| 5 | 离线补发调 `doSend()`，全页无此函数 | 联网后补发静默失败 |

修完这五个，脚本终于能跑了，但**主内容仍是一片黑**——再挖：

| # | 病 | 后果 |
|---|---|---|
| 6 | 同一次迁移加了 `.pager,.pages{display:none!important}` 锁死旧容器，**而新容器 `.tab-panels` 从没建进 HTML**（全页 0 个） | 三个页面（枢机/对话/设置）永久不可见，只剩顶栏底栏 |
| 7 | 切页位移按容器宽算（容器宽＝3 屏） | 划一下飞出三屏 |
| 8 | `#pages` 里混着 `#voiceScrim` 语音浮层，被当成第 4 页 | 步长变 1/4，**第三页永远划不到** |
| 9 | `PAGES` 常量全页从未定义 | 该行必抛异常被 catch 吞掉 |
| 10 | `fmtTs` 定义在靠后的 script 块却被主块启动时调用（5 处） | 启动即报错 |

**实测验证**（无头浏览器 + 主人令牌走完整登录）：启动零报错；
首页高度 **0 → 880px**；三页切换位移 `0% / -33.33% / -66.67%`，全部到达。

### 2. Telegram 入站从来没通过

**症状**：它能主动发消息给权哥，权哥发给它却石沉大海。

**根因**：三处叠加。

1. 回调注册在 `aquan.lufei.uk/tg`，但该域名已指向另一套旧服务 `nexus-core`，
   只收 GET，Telegram 的 POST 全被 405 弹回。
2. `/tg` 路由把**未声明的 `ctx`** 传给处理器 → 每条消息必抛 ReferenceError → 500。
   （Durable Object 的 `fetch(request)` 本就没有 ExecutionContext。）
   更阴的是处理器把「调大脑 + 回消息」全放在 `ctx?.waitUntil?.()` 里，
   光传 `undefined` 会被**静默跳过**——Telegram 收 200、权哥收不到回话，比 500 更难查。
3. `handleTelegramWebhook` 内 7 处调用 `json()`，而 `json` 是 `_fetch` 的局部函数，
   方法作用域里根本看不见 → 走到任意 return 都抛 ReferenceError。

**修法**：门牌改以 `PUBLIC_URL` 为准（自定义域可能被改指，"最近访问来路"不可信）；
`ctx` 换成接住后台任务并 await 的垫片；就地补 `json` 实现。
**实测**：积压 3 条清零，此后零报错，权哥收到了带枢语坐标的真回话。

### 3. 大脑网关是个死域名

神枢的大脑网关配在 `https://aquan.love:8443/v1`，而 **`aquan.love` 根本没有 DNS 解析记录**
（只有 `www.` 子域有）。Cloudflare error 1016 的定义就是这个。所以它够不着自己的脑子。

**修法（待权哥执行）**：网关直指 `https://api.anthropic.com`。
神枢**已内建支持** `sk-ant-oat` 型 OAuth 令牌（自动 Bearer + oauth beta 头），无需改代码。
自建中转站那一跳纯属绕路，而绕的那段坏了。

  一条命令装 systemd（专用非特权账号 + 只授 NET_RAW/NET_ADMIN）。CI 真机 15/15 过。
- **安全收敛**：顶层兜底报错只回主人，未鉴权调用方只拿错误编号。

## 三、最重要的沉淀：页面健康守门

今天的核心教训不是那些 bug，而是：**界面死了 15 天，所有测试照样全绿**——
因为 selftest 与单测**从不加载页面**。故立 `ui_health.test.mjs` 四道关卡并接进 `npm test`：

| 关卡 | 防的故障 |
|---|---|
| ① 每个内联 script 语法必须正确 | 界面看得见点不动 |
| ② 顶层 `let/const` 跨块不得重名 | 整块脚本静默死掉 |
| ③ `onclick` 调用的函数必须存在 | 死按钮 |
| ④ 主内容容器不得被隐藏 / 不得有「只有样式没有元素」的半拉子容器 | 主内容一片黑 |

关卡立起来当场就抓出：推送设置页 4 个死按钮（`loadPushInfo` 等全页从未定义，
后端接口和前端实现都现成，纯粹名字没接上）+ 那套孤儿 `.tab-panels` 样式。均已清理。
