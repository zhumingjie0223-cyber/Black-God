## 总结

本次真正的产出不是"重推上次的 commit"——核实下来上次那笔 `9e6249d` 早就在 main 上了，
所谓"push 失败"是误判。真正有价值的是**复核时挖出的 5 个新 bug**，全部有测试钉住：

1. **LEASE_TTL 配置从来没生效过**：上一版写在模块顶层读 `process.env`，
   而模块求值发生在 isolate 启动时、根本拿不到绑定。commit message 承诺
   "改为 env.AGENT_LEASE_TTL_MS 可配置"，实现却没兑现。已改为构造时从 DO 的
   `env` 解析，并把"空串=没配"和"配成 0 要钳到下限"分开处理。
2. **枢语源头落后于消费副本**：`web/nexus-do/lexicon.js` 早已硬化，
   权威源头 `shuyu/lexicon.js` 和 `shuyu_engine.py` 没跟上，方向反了。已回填。
3. **encode 不是单射**：`Ao-cor-is-·qi` 这类畸形词冒领合法编号 0，跨仓语义会错位。三侧已统一拒绝。
4. **JS 与 Python 判定分叉**：`Ao-cor-is·qi·qi` 一侧返回 0、一侧返回 -1。已对齐。
5. **matchWord 崩溃**：词包只带 `vocab` 不带 `word_ids` 时抛 TypeError。已降级为 `id: null`。

**根因**：`check-sync.mjs` 只采样合法编号做往返，从不喂畸形输入，
所以三侧错误处理分叉长期没人发现。已给它补上畸形输入与 decode 守卫两道校验，
堵住这一类漏网。
