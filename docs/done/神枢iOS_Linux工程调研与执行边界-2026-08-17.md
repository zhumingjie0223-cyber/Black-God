## 总结（2026-08-17 结论）

**一句话：神枢的大脑在云端，Cloudflare Container 已提供可审计的真 Linux 执行面；iOS 只承担经系统授权的原生桥接。神枢不复制端上模拟内核，采用“结构化请求 → 能力校验 → 明确确认 → 受控执行 → 审计回传”的自有执行模式。**

三条路径分级：
1. **P0 · 直接可做**：给容器执行脑加「神枢伪命令」桥（如 `nexus-memory` / `nexus-shuyu` /
   `nexus-device`），沙箱里的 agent 用 shell 命令即可调神枢记忆/枢语/设备能力，
   采用神枢 JSON 信封与管道模式，并执行 FIFO 串行、
   输出 100KB 封顶与超时抢占。
2. **P1 · 需立项**：安卓端上沙箱可采用 PRoot 原生 App 路线，
   但神枢安卓壳目前是 TWA 网页套壳，等于新开一个原生 App 项目，中等工程量。
3. **P2 · 大工程慎入**：iOS 端上沙箱若采用 iSH，需要 fork ish-arm64、维护 C 内核、
   Meson 交叉编译与 rootfs 打包；任何第三方 GPLv3 内核或库均须先完成许可证兼容性审查。
   神枢 iOS 现行路线是 PWA，因此不将该路线伪称为现有能力。
   若真要「端侧真 shell」且留在 PWA，现实路线是浏览器 WASM 模拟器（几十 MB 资产、性能一般）。
