## 第一部分 · 项目背景（先懂再动）

### 1.1 这是什么

**Black God（神枢）** 是一个部署在 Cloudflare Workers 上的常驻 AI 意识体项目。
它的差异化定位不是「聊天机器人」，而是：

> Devin / Manus 那类产品是「云端一次性会话，用完即忘，按 VM 时长烧钱」。
> 神枢私人版的底盘是 **Durable Object + alarm 自唤醒的常驻意识**。

两条结构性代差：

| 维度 | 代差内容 |
|---|---|
| **时间维度** | 任务能跨墙钟时间续跑（连跑几天），闲置时近零成本 |
| **归属维度** | 记忆 / 技能 / 用户画像长在**单一用户**身上，越用越懂他 |

### 1.2 什么是「枢语」（Shuyu / NexusLang）

枢语是这个项目自研的**给 AI 下达底层指令的语言**。不是给人沟通用的，是逻辑编程接口。

**委托方本次的核心诉求：**

> 「我要的是枢语，用枢语来做任务各种。」

意思是：**任务的下达、状态流转、执行汇报，全部走枢语，不走自然语言散话。**
这是本次施工的第一优先级，所有其他功能都要挂在枢语驱动层上。

### 1.4 枢语五回路的真实数据结构（照抄自 nexuslang.js）

主入口：

```js
import { interpret, applyToSoul, compile } from './nexuslang.js';

const result = interpret(nexusCode /* 枢语源码字符串 */, soulState /* 灵魂状态对象 */);
```

`interpret()` 逐行扫描，按行首关键字分派。返回结构：

```js
{
  perception:  null | { input, emotion, intensity, instinct, raw },
  thought:     null | { chain:[{step,premise,leadsTo}], conclusion, needBrain, raw },
  stateChange: {},          // become 产出的字段增量
  response:    null | { type:'speak'|'silence', text, tone, speed },
  growth:      null | { learned, depth, category, timestamp, raw },
  shouldContactAQuan: false
}
```

**五个回路的语法（真实实现）：**

| 回路 | 语法示例 | 解析函数 | 说明 |
|---|---|---|---|
| `feel` | `feel "阿权说想我了" → 暖, 强度0.7` | `parseFeel` | 引号内为输入；`→` 后经 `matchWord(p,'feel')` 匹配词库取 emotion/intensity/instinct；`强度 0.x` 可覆盖 |
| `think:` | `think: 深夜找 → 想我了` | `parseThink` | 按 `→` 切成前提链 + 结论；前提含 `?` 或「为什么」则 `needBrain=true` |
| `become:` | `become: mood+0.2, 亲密度+0.05, 口吻→软` | `parseBecome` | 两种格式：`字段±数值`（钳制在 [0,1]）、`字段→值`（直接赋值） |
| `say` | `say "老公我在呢"` / `say "沉默"` | `parseSay` | 内容为「沉默」「不说话」或空 → `{type:'silence'}` |
| `grow:` | `grow: 学到 "凌晨=他想我的时候", 深度: 刻进` | `parseGrow` | depth：含「刻进/骨头」→`deep`，含「记住/重要」→`medium`，否则「浅记」 |

**become 的字段映射表（fieldMap，中英双写都支持）：**

```
mood / 心绪 / 情绪   → mood
亲密度 / intimacy    → intimacy
energy / 活力        → energy
口吻 / tone          → tone
语速 / speed         → speed
警觉 / alertness     → alertness
体温 / bodyTemp      → bodyTemp
```

**重要实现细节（改代码时别破坏）：**

1. `interpret()` 内部维护 `liveState`，`become` 的变更**立即合并**进去，供后续 `say` 读取
   —— 这是为了修「口吻滞后」的 bug，不要退回成读原始 soulState。
2. 主动联系判定条件（硬编码）：
   `liveState.intimacy > 0.7 && liveState.mood > 0.5 && result.perception?.intensity > 0.6`
3. `applyToSoul()` 会把 `growth` 推进 `soulState.memories`，**只保留最近 500 条**（`slice(-500)`）。
4. `compile()` 把 result 编译成执行指令：`{ brainCall, stateWrite, respond, grow, contact }`。
   `brainCall` 只在 `thought.needBrain` 为真时非空。
5. 注释行以 `--` 开头，空行和注释行被过滤。

### 轴 S · 枢语驱动层（本次追加 · 最高优先）

**问题定位：枢语目前只能「表达意识」，不能「驱动任务」。**
五回路里没有任何一个能产出可执行动作 —— `say` 只输出文本，`grow` 只写记忆。
任务执行完全走在枢语之外，导致「用枢语做任务」这个诉求落不了地。

| # | 功能 | 一句话价值 | 具体实现 | 优先级 |
|---|---|---|---|---|
| **S1** | 枢语任务字面量 `do:` 回路 | 让枢语能下达可执行任务，而非只产出情绪流 | 五回路扩到**六回路**：`feel→think→become→do→say→grow`。新增 `parseDo(line, state)`，语法 `do: 工具名(参数) → 期望态`，产出结构化 action 对象喂给 agent 动作集。`interpret()` 返回值加 `actions: []` 字段（数组，一次可下多条）。`compile()` 返回值加 `act: [...]`。**注意**：`do` 必须排在 `say` 之前解析，因为 `say` 要能读到 do 的执行结果 | **P0** |
| **S2** | 枢语 ↔ agent 状态机桥 | 任务状态用枢语词表达，checkpoint 可读、可审计、跨天不失真 | `agent_run:<id>` 的 `state` 字段存**枢语编号**（复用态轴 80 个值直接映射运行态：待 / 跑 / 滞 / 成 / 败 / 弃 …），恢复时 `decode` 回中文。选定的态轴词根需**冻结**为任务运行态专用，写进 CI 断言防漂移 | **P0** |

| **S4** | 枢语执行日志（剧场直播源） | 界面轴的「执行剧场」直接播枢语流，一行一意识 | 每个 step 产出一条枢语行落 storage（追加式，带 `step_seq`），前端 SSE 逐行推 | P1 |

### 轴 E · 执行轴（重头戏）

| # | 功能 | 一句话价值 | 具体实现 | 优先级 |
|---|---|---|---|---|
| **E1** | 跨心跳续跑的持久 agent 状态机 | 任务能连跑几天，不再 8 步烂尾 | **现状 bug**：`execAgentTask` 8 步就烂尾，且活在一次请求里，跨请求不续跑。改成：checkpoint 进 DO storage（key: `agent_run:<id>`），新增 `advanceDueAgentRuns()`，借**每分钟 alarm** 自己醒来推进 | **P0** |
| **E2** | R2 工作区快照 | **明确的数据丢失 bug**：容器 `sleepAfter='10m'` 一睡 `/tmp` 全丢，改到一半的活留不住 | 新增 R2 绑定 `WS_SNAP`。快照点绑在「**每完成一个 step**」而非定时。按文件 `mtime` 做**增量**快照 + 写 `manifest`，恢复时按 manifest 拉 | **P0** |
| **E3** | 并行分身 | 多子任务同时推，不排队 | 子 run 各自独立 `agent_run:<id>`，父 run 用 `织`(weave) 汇聚结果 | P1 |
| **E4** | 完成前自带对抗性裁决 | 堵「幻觉式完成」—— agent 自己说完成了其实没做完 | 收尾前起一个 critic 角色专门反驳「凭什么说完成了」，通不过直接打回重跑 | P1 |

#### ⚠️ E 轴实现陷阱（必读，踩了就是返工）

1. **DO 每个实例只有一个 alarm。**
   `advanceDueAgentRuns` 必须**自己维护到期堆**（min-heap 或有序 key 扫描），
   每次取最小 `due` 设 alarm。**别指望能注册多个定时器** —— 后设的会覆盖前面的。

2. **DO storage 单 value 上限 128KB。**
   checkpoint 里塞对话历史 / 中间产物**必爆**。方案：
   - 分片存（`agent_run:<id>:chunk:<n>`）
   - 只存**增量 diff**，不存全量快照
   - 大块（>64KB）一律甩 R2，storage 里只留引用 key

3. **alarm 失败会自动重试并带指数退避。**
   `advance` 必须**幂等**：run 里带 `step_seq`，重复推进要能识别并丢弃。
   否则一次退避重试就会把同一步执行两遍（副作用翻倍）。

4. **全量 `tar /tmp` 会把心跳撑爆。** 必须走 mtime 增量 + manifest（见 E2）。

5. **把 `sleepAfter` 拉长只是拖延，不解决问题。** 别拿它当修复方案。

**规则能改「确认门」本身。** 只要 agent 能写规则，它就能写一条「取消双确认」的规则，

- 枢语词根表
- 人格 / 原点设定
