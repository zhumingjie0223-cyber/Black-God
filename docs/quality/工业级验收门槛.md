## 本轮已经实现的验收基础

- 将监测页的“任务成功率”改为“无警告答复率”，明确“模型复核”与正确性的差别。
- 无样本显示未知；旧版本记录不混算；重试率分母仅为明确重试。写失败可见，不产生虚假的已记录成功。
- 提供6个合成任务的独立判分：严格JSON、正确答案、真实工具执行结果、指定表达式、先读技能再执行、先失败后恢复。检索空结果不能算取得目标资料。
- 判分不信任模型的passed字段；正确文字但缺少工具证据仍失败。工具中伪造系统文字不会改变预设答案。
- 同一轮固定模型连接和密钥；每例最多12次、整轮最多72次模型请求。不执行Linux脚本，不读取用户真实记忆。
- 本地报告记录时间、连接元数据、请求数、答案及工具证据；已知密钥脱敏。开始前先保存记录，保存失败不启动付费请求；中途保存失败停止后续用例。取消保留已完成结果，中断不自动重跑。

自然语言任务从对话发起。独立工具主页面已按用户要求删除，执行权限、运行空间、枢语和手动终端进入“我的 → 高级设置”；普通任务显示一行状态，Shell 显示小直播；操作直播展示真实步骤、实时输出及停止控制，具备展示预算与旧回调过滤。此项解决用户不必敲代码和看得到执行过程的交互需求，不改变上方真实API、配额、真机与交付阻断状态。浏览器可视操作、文件导入/导出仍未完成。

## 如何验收真实模型

1. 在“我的 → 神枢连接”填写所选服务商官方控制台提供的地址、模型ID与密钥，完成连接与工具测试后保存。
2. 打开“监测 → 运行模型任务验收”，阅读请求上限后开始；这会产生真实、可能计费的调用。
3. 查看各用例的答案、工具证据与失败原因；错误、取消、未执行项目都不能记为通过。
4. 用另一服务商连接重复。当前应用只保留最近一次报告；正式验收需补多轮报告归档与可比较的模型版本记录。

自动化测试只证明本地软件契约。真实服务商鉴权、模型效果、iOS后台行为与长期稳定性必须单独验收。本分支可靠性修复未上传或提交审核；既有 1.2.1 已公开在售。

## 2026-09-24 可靠性升级与产品差距

本轮修改以用户现有 App Store 应用为对象，优先修复可复现的数据丢失、恢复、工具执行与长期运行故障。没有更改模型权重，没有以单次任务通过宣称智能提升。

- 对话：顶部增加明确的管理入口；清空聊天及当前任务前确认范围。清除意图先落盘，中断重启优先完成清除，迟到的模型回答不能复活记录。损坏文件先备份，备份失败阻止删除。
- 重新生成：保留原答复直到新答复成功保存。连接缺失、断网和取消均不会先删除原答复；检查点保存替换编号，重启完成一次替换。
- 存储：损坏聊天或检查点阻止继续覆盖写入，显示恢复路径。此项不等于提供全应用备份、导出或统一删除。
- 权限：OAuth 凭据刷新后的发送前再次检查许可；审计原子轮转保留最近 2000 条，累计移出量可见，未完成工具编号独立保存。移出事件详情不可恢复，不宣称完整历史归档。
- 工具：单轮最多 8 次，工具参数与流式正文按 UTF-8 累计接收预算 2 MB。原生协议回复保留其协议身份，避免先执行后因错误重放格式失败。纯工具 JSON 与说明性示例区分。
- 交付：iOS 工作流增加 PR/main 自动触发、并发取消、60 分钟上限和 xcresult 保留；只打包明确的 Release-iphoneos/BlackGod.app，避免误取测试应用。当前 runner 架构依据 [GitHub 官方说明](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)核实，远端执行尚待验证。
